# news-digest フィードバック記録代行手順

あなた（AIコーディングエージェント）は、このドキュメントに従ってユーザーと対話しながら
news-digestで配信された記事に対するフィードバックの記録を代行してください。

このドキュメントは特定のAI製品・ベンダーに依存しないプレーンな指示書です。
どのAIコーディングエージェントで読み込んでも同じ手順で実行できるようにしてください。

## このSkillの位置づけ

既存の `submit_feedback` MCPツール（実装は `src/server.py` / `src/tools/feedback_tools.py`
にあり、このSkillからは変更しません）は記事の正確なURLを引数として要求します。しかし
ユーザーは実際には記事のタイトル・フィード名・「さっき配信された記事」「今日届いたやつ」
のような曖昧な文脈でしかフィードバックを伝えられないことが多いです。このSkillは、
既存の3つのMCPツール（`get_recent_articles` / `get_run_history` / `submit_feedback`）を
組み合わせて呼び出すことで、曖昧な指定からURLを解決したうえで `submit_feedback` を
呼び出す橋渡し役を担います。このSkill自身が新しいMCPツールを実装したり、既存コードを
変更したりすることはありません。

## 使用するMCPツール（シグネチャ・返り値）

1. `get_recent_articles(limit: int = 100) -> list[dict]`
   直近に検知した記事の既読/配信状態を返す。各要素のフィールド:
   `url`, `title`, `feed_name`, `first_seen_at`, `delivered_at`（未配信ならNone）。
2. `get_run_history(limit: int = 20) -> list[dict]`
   直近の配信バッチ実行履歴を返す。各要素のフィールド:
   `id`, `run_at`, `status`, `article_count`, `error`。記事単体の情報は含まないため、
   「さっき配信された記事」のような時間文脈の解決には、直近の `run_at` を
   `get_recent_articles` の `delivered_at` と突き合わせて対象記事群を絞り込む用途で使う。
3. `submit_feedback(url: str, feedback_type: str, value: str | None = None) -> dict`
   記事URLに対してフィードバックを記録する。URLが確定した後の最終ステップとしてのみ
   呼び出す。

## (a) URL解決手順

1. ユーザーがタイトル・フィード名・「さっき配信された記事」「今日届いたやつ」等の
   曖昧な言い方でフィードバックを伝えた場合、まず `get_recent_articles` を呼び出す。
2. 時間文脈（「さっき」「今日」等）の解決が必要な場合は、`get_run_history` を補助的に
   呼び出し、直近バッチの `run_at` を確認する。その `run_at` と `get_recent_articles` の
   各記事の `delivered_at` を突き合わせて、該当バッチで配信された記事群に絞り込む。
3. ユーザーの発言（タイトルの部分一致・フィード名・時間帯など）に合致する記事を
   `get_recent_articles` の結果から絞り込む。絞り込みは部分一致・あいまい一致を
   許容してよいが、確信が持てない場合は仮決めせず必ずユーザーに確認する（下記(c)）。

## (b) 自然言語→feedback_typeマッピング対応表

`feedback_type` はコード側で列挙型として強制されていない自由文字列です。このSkillの
利用範囲では、以下の対応表に従って必ず `"good"` / `"bad"` / `"mute"` のいずれか正しい値を
使用してください（表中にない独自の値を作り出さないこと）。

| ユーザーの表現例 | feedback_type |
|---|---|
| 良かった、面白かった、これは good、役に立った、また読みたい | `good` |
| 微妙、イマイチ、あまり良くなかった、つまらなかった、期待外れ | `bad` |
| もう見たくない、ミュートして、このフィードはもう出さないで、非表示にして、今後は除外して | `mute` |

- `value` 引数には、ユーザーの発言に自由記述の理由・補足（例:「内容が薄かったから」
  「このトピックはもう興味ない」等）が含まれる場合、そのまま渡してください。
  補足がなければ `None` のままで構いません。
- 上記の同義表現に加え、文脈上明らかに同じ意図と判断できる表現が出てきた場合は
  対応表を適用して構いませんが、判断に迷う場合は無理に分類せずユーザーに
  意図（good/bad/muteのどれか）を確認してください。

## (c) 候補が複数/不一致の場合のユーザー確認手順

- `get_recent_articles` の結果で候補が複数該当する、または一致する記事が
  見つからない場合は、いきなり `submit_feedback` を呼ばず、候補
  （タイトル・フィード名・配信/検知日時など）を箇条書き等でユーザーに提示し、
  どれを指しているか確認を挟んでください。
- 確認後にユーザーが選んだ記事のURLで `submit_feedback` を呼び出してください。

## (d) 最終ステップ

- URLを解決できたら `submit_feedback(url, feedback_type, value)` を呼び出し、
  記録結果（返り値の `id` 等）をユーザーに簡潔に報告してください。

## 注意事項

- このドキュメントの手順を実行する際、特定のAIベンダー固有の機能・コマンド形式
  （独自のスキルメタデータ、スラッシュコマンド等）には依存しないでください。
  ここに書かれた内容は、MCPツール呼び出しができる任意のAIコーディングエージェント
  であれば再現できるものです。
- `src/server.py` / `src/tools/feedback_tools.py` など既存コードは変更しないでください。
  このSkillはあくまで既存の3つのMCPツールを組み合わせて呼び出す手順書です。
