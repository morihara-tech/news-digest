# news-digest セットアップ代行手順

あなた（AIコーディングエージェント）は、このドキュメントに従ってユーザーと対話しながら
news-digestのセットアップ（`.env`・`config.yaml`の生成、依存関係のインストール、
妥当性検証、試験実行）を代行してください。

このドキュメントは特定のAI製品・ベンダーに依存しないプレーンな指示書です。
どのAIコーディングエージェントで読み込んでも同じ手順で実行できるようにしてください。

## 0. 前提確認（最初に必ず行うこと）

作業を始める前に、リポジトリ直下に既存の `.env` ファイルおよび `config.yaml`
ファイルが存在するかを確認してください。

- どちらか（または両方）が既に存在する場合、**無断で上書きしてはいけません**。
  該当ファイルの内容をユーザーに提示した上で、以下のいずれかを選んでもらってください。
  - 既存の内容を上書きしてよい
  - 既存ファイルは残し、別名（例: `config.new.yaml`）で新しい内容を保存する
  - セットアップを中断する
- `.env` には秘密情報（APIキー・Webhook URL）が含まれる可能性があるため、
  内容を対話ログや外部に送信・要約表示する際は値そのものを引用しないよう注意してください。
  ファイルの有無や設定済みキー名（例: `ANTHROPIC_API_KEY=` の行があるか）だけを
  確認すれば十分です。
- どちらも存在しない場合は、そのまま新規作成に進んでよい旨をユーザーに伝えてから続行してください。

## 1. ヒアリング項目

以下の項目をユーザーに順番に、または関連する項目をまとめて確認してください。
一度に大量の質問を投げず、ユーザーが答えやすい単位に区切ることを推奨します。

### 1-1. LLMプロバイダー

`claude` / `local-ai` / `claude-code-cli` のどれを使うかを確認してください。

- **`claude` の場合**
  - Anthropic APIキーを既に持っているかを確認してください。
  - APIキーの値そのものを対話（チャット入力・ログ）に貼らせないでください。
    `.env` ファイルの `ANTHROPIC_API_KEY=` の行に、ユーザー自身がエディタや
    シェルコマンドで直接書き込む（貼り付ける）よう案内してください。
    あなたはそのキーの値を受け取らず、ファイルへの書き込みが完了したことだけを
    確認してください。
  - `llm.model` に設定するモデルID（例: `claude-sonnet-4`）を確認してください。
    分からない場合は `config.example.yaml` の既定値のままでよいか尋ねてください。

- **`local-ai` の場合**（Ollama等のOpenAI互換API）
  - ベースURL（例: `http://localhost:11434/v1`）を確認してください。
  - 使用するモデル名（例: `deepseek-r1:14b`）を確認してください。
  - このプロバイダーではAPIキーは不要である旨を伝えてください。

- **`claude-code-cli` の場合**
  - CLIの実行コマンド名（既定 `claude`）を確認してください。
  - タイムアウト秒数（既定 300秒）を確認してください。
  - 失敗時の再試行回数（既定 1回）を確認してください。
  - このプロバイダーでは `.env` にAPIキーを設定する必要がない旨を伝えてください。

### 1-2. 配信先

Slack / Google Chat のどちらを使うか（両方の設定も可能）を確認してください。

- 使用する配信先ごとに、Incoming Webhook URLをヒアリングしてください。
  - Webhook URLも秘密情報に準じるため、可能であればAPIキーと同様に
    ユーザー自身が `.env` に直接書き込む方法を案内してください。
- 複数の配信先を有効にする場合は、`config.yaml` の `delivery` を配列として
  複数エントリ用意する必要がある旨を伝えてください。

### 1-3. 購読フィード

購読したいRSS/Atomフィードを1件以上ヒアリングしてください。フィードごとに
以下を確認してください。

- 名前（`name`）
- フィードURL（`url`）
- カテゴリ（`category`、任意）
- そのフィード固有のキーワードフィルタ（任意、下記1-4参照）

複数フィードがある場合は、まとめてリストで受け取っても構いません。

### 1-4. フィルタキーワード（任意）

全体（グローバル）フィルタとして、以下を確認してください。

- 含めたいキーワード（`filters.include_keywords`、空でも可）
- 除外したいキーワード（`filters.exclude_keywords`、例: `PR`, `広告`）

フィード単位で個別のフィルタを設定したい場合は、そのフィードの `filters` に
反映してください。

### 1-5. 主要パラメータの確認

以下の項目について、デフォルト値のままでよいかをユーザーに確認してください。
変更したい場合のみ値をヒアリングしてください。

- `digest.max_articles`（1回の配信件数上限。既定20）
- `schedule.notify_on_empty`（新着0件の日も通知するか。既定true）
- `schedule.timezone` / `schedule.times`（これらの値は、後述の2-5節で
  `news-digest schedule install` を実行するとOSスケジューラ（cron/systemd/launchd）
  へ実際に自動登録され、配信バッチの起動時刻を決定します）
- `retention.seen_ttl_days`（既読とみなすTTL日数。既定90）

## 2. 実行手順

ヒアリングが終わったら、以下を順番に実行してください。

### 2-1. `.env` と `config.yaml` の生成

- `config.example.yaml` をベースに、ヒアリング結果を反映した `config.yaml` を作成してください。
- `.env.example` をベースに、必要な環境変数名の行を用意した `.env` を作成してください。
  APIキー・Webhook URLの値自体は、前述のとおりユーザー自身に書き込んでもらってください。
- ファイルを書き込む前に、手順0で確認した上書き方針（上書き/別名保存/中断）に従ってください。

### 2-2. 依存関係のインストール

```bash
uv sync
```

を実行してください。失敗した場合はエラー内容をユーザーに提示し、対処方法
（uvのインストール状況確認など）を一緒に検討してください。

### 2-3. 設定ファイルの妥当性検証

生成した `config.yaml` が正しく読み込めるかを、以下のようなワンライナーで検証してください。

```bash
uv run python -c "from src.config import load_config; load_config('config.yaml')"
```

- 例外なく終了すれば妥当性検証は成功です。
- エラーが発生した場合は、エラーメッセージをそのままユーザーに提示し、
  該当する設定項目について再ヒアリングして `config.yaml` を修正し、再検証してください。
  検証が通るまでこのステップを繰り返してください。

### 2-4. 試験実行の提案

妥当性検証が通ったら、以下のコマンドでの試験実行をユーザーに提案してください
（実行するかどうかはユーザーの判断に委ねてください。Webhookへの実際の配信が
発生する可能性があるためです）。

```bash
uv run news-digest --config config.yaml --db state/digest.db run
```

グローバルオプション（`--config` / `--db`）はサブコマンド（`run`）より前に
指定する必要があります。順序を誤らないよう注意してください。

ユーザーが実行に同意した場合は、実行後にログの内容と、Slack/Google Chatへの
配信が成功したかどうかを一緒に確認してください。失敗している場合は、
ログの内容をもとに原因（Webhook URLの誤り、APIキー未設定など）を切り分けて
案内してください。

### 2-5. スケジュール登録（同意ベース）

試験実行の確認が済んだら、`schedule.timezone` / `schedule.times` に従って
配信バッチを定期実行するために、OSスケジューラ（cron/systemd/launchd）への
登録を以下の手順で進めてください。試験実行と同様、ユーザーの同意なしに
登録コマンドを実行しないでください。

1. まず登録内容をプレビューするため、以下のコマンドを実行してください。

   ```bash
   uv run news-digest --config config.yaml --db state/digest.db schedule preview
   ```

   グローバルオプション（`--config` / `--db`）はサブコマンド（`schedule`）より
   前に指定する必要があります。順序を誤らないよう注意してください。

   このコマンドは実際には何も登録せず、どのスケジューラ（cron/systemd/launchd
   のいずれか。未指定時はOS判定に基づき自動選択されます）が選ばれたか、また
   実際に登録される内容（crontabの行、systemd unit/timerファイルの内容、
   launchd plistの内容のいずれか）を標準出力に表示するだけです。

2. `preview` の出力をそのままユーザーに提示し、この内容で登録してよいか
   同意を得てください。同意が得られるまで次のステップに進まないでください。

3. 同意が得られたら、以下のコマンドで実際に登録してください。

   ```bash
   uv run news-digest --config config.yaml --db state/digest.db schedule install
   ```

   このコマンドは冪等です（既に登録済みの場合は内容を更新するだけで、
   重複登録はされません）。

4. `install` が失敗し、非ゼロ終了した場合は、コマンドが標準出力に表示する
   手動設定手順をそのままユーザーに提示し、その場で案内を完結させてください。
   README等の別ドキュメントを参照するよう誘導せず、表示された手順（ラッパー
   スクリプトの作成方法、cron/systemd/launchdそれぞれの手動設定内容）を
   使ってその場で対応方法を案内してください。

## 3. 注意事項

- このドキュメントの手順を実行する際、特定のAIベンダー固有の機能・コマンド形式
  （独自のスキルメタデータ、スラッシュコマンド等）には依存しないでください。
  ここに書かれた内容は、ファイル読み書きとシェルコマンド実行ができる任意の
  AIコーディングエージェントであれば再現できるものです。
- `.env` や `config.yaml` に含まれる秘密情報（APIキー・Webhook URL）を、
  対話ログ・コミット・外部サービスに送信しないよう常に注意してください。
- セットアップ完了後、`.env` と `config.yaml` がGit管理対象外であること
  （`.gitignore` に含まれていること）を確認し、誤ってコミットしないよう伝えてください。
